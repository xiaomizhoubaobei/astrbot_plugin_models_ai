# =============================================================================
# CI 工具链依赖（**版本 + 哈希双锁定**，非插件运行依赖）
# =============================================================================
# 用途：coverage.yml / security-scan.yml 等 GitHub Actions 工作流所需的
#       测试与扫描工具。安装方式统一为：
#
#           pip install --require-hashes -r requirements-ci-tools.txt
#
# ── 为什么要单独一份清单（而不是写在 workflow 里 `pip install pytest`）────────
#  1) 供应链安全（Scorecard `PinnedDependenciesID`）：工作流里的 `pip install bandit`
#     属于「未固定版本的依赖安装」，上游随时可以换掉包内容，攻击者只需接管一次
#     发布账号即可让 CI 执行任意代码。锁定 `==版本 + sha256` 后，包内容一旦变化
#     安装即失败（fail-closed），而不是静默装上一个「同名新版」。
#  2) 用 `--require-hashes` 时 pip 会**强制校验**每一份下载的哈希，并要求
#     **所有**依赖（含间接依赖）都被锁定，因此本文件是完整的依赖闭包。
#  3) 放在仓库里而不是工作流里：可被 Dependabot 的 `pip` 生态自动升级（见
#     .github/dependabot.yml），版本漂移可审查、可回滚，而不是散落在 YAML 里。
#
# ── 与插件运行依赖的边界 ───────────────────────────────────────────────────
#  本文件**不是**插件运行依赖（那是 requirements.txt，走版本下限以满足 AstrBot
#  宿主的依赖解析）。本文件只服务于 CI 里的「跑测试 / 跑扫描」这一步。
#
# ── 多版本矩阵的兼容性（重要，勿删）─────────────────────────────────────────
#  CI 矩阵覆盖 Python 3.13 / 3.14 / 3.15，而 `--require-hashes` **不会**按当前
#  解释器自动挑 wheel：它要求本文件提供的候选里**必须有一个能装上**。因此每个
#  含 C 扩展的包（black / coverage / pyyaml）都按 cp313 / cp314 / cp315 及通用
#  wheel 分别列出哈希，覆盖「有对应 wheel」与「回落到通用 wheel」两种情形；
#  纯 Python 包只有一份。⚠️ 新增 C 扩展依赖时务必同样补齐各解释器标签的哈希，
#  否则矩阵中某个版本会因「找不到匹配分发」而安装失败。
#
# ── 升级方式（二选一）──────────────────────────────────────────────────────
#  · 推荐：等 Dependabot 的 `ci(deps)` PR（它会把版本与哈希一起改掉）；
#  · 手工：改版本号后按下述命令重新生成哈希并补齐各解释器标签：
#        pip download --no-deps -d /tmp/w --python-version 3.13 \
#          --only-binary=:all: --implementation cp --abi cp313 \
#          --platform manylinux2014_x86_64 <包名>==<新版本>
#        sha256sum /tmp/w/*.whl
# =============================================================================
